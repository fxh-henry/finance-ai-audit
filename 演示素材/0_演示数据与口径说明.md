提交按钮原文：「**提交报销单，进入财务终审**」（左边那颗是「保存报销单」，只存草稿不进审核）。

### 口径

- 折算每晚每间 = 2584 ÷ 4 晚 ÷ 1 间 = **646.00 元/晚**
- 标准 = 一线城市 × 普通员工 = **400 元/天**（《通用企业报销制度》第十四条）
- **超标 246 元/晚**

### 为什么这几项要这么填

| 填法 | 原因 |
| --- | --- |
| 入住城市 = 北京 | 工具靠城市定档。系统里北京是唯一确定的「一线城市」，不会出现口径歧义 |
| 住宿晚数 = 4、房间数 = 1 | 折算得 646 元/晚，与 `iCAN应用方案.pdf` 图 2 的截图完全一致，文档与视频可互相印证 |
| 入住人姓名、参与人都 = 张三 | 避免 Agent 额外判出「入住人与报销人不一致」，让不通过的理由集中在**超标**这一条主线上 |
| 报销金额 = 2584 | 与发票价税合计一致，不引入额外疑点 |

> 提示：01 号票的备注里写的是「入离店日期 2026-07-23 至 2026-07-26 共 3 晚」，备注内容在界面上不会展示、也不进 Agent 提示词，因此填 4 晚不会产生矛盾。若评委追问，按「住宿晚数以报销单申报为准，系统按申报晚数折算单价」回答即可。

## 三、终审预期结论

- 结论：**不通过**
- 主要理由：住宿费超标（646 元/晚，标准 400 元/天，超标 246 元）
- 次要理由：发票种类为「电子发票（普通发票）」，而第十四条说明第 3 项要求住宿费提供增值税专用发票
- 条款依据：《通用企业报销制度》第十四条 住宿费标准
- 防幻觉校验：结论可溯源，判「不通过」有条款依据，通过

## 四、反思机制为什么一定会触发（可用于答辩）

反思的触发条件是命中白名单校验项，其中一条是「**工具判定与制度一致性**」：费用标准工具判了超标、且本轮检索到的制度原文里出现例外表述时命中。本案三个条件同时成立：

1. 费用标准工具返回 `passed = False`（646 > 400），且不是「系统没配标准」
2. Agent 为引用条款必然调用 `rag_policy_search_tool`；实测「住宿费标准」「出差住宿费超标如何处理」等问法，检索 Top-1 都命中「第十四条 住宿费标准」整块（521 字符，说明段未被切块切走）
3. 该原文含例外词：`特殊情况`、`提前审批`、`由个人承担`、`实报实销`

→ 命中 `工具判定与制度一致性`（warn）→ `should_reflect` 返回 True → 进入反思轮。

收敛规则（`utils/reflection.py` 的 `reconcile`）：

- 结论**收紧**（通过 → 不通过）：直接生效
- 结论**放宽**（不通过 → 通过）：必须同时新增一次工具调用**和**一条新条款引用，否则维持第一轮
- 只给一轮机会（`REFLECTION_MAX_ROUNDS = 1`）

因此本案的预期表现是：Agent 追加一轮检索、确认「超标部分由个人承担、特殊情况需提前审批」的处置方式，**结论稳定维持不通过**。这正好演示了「结论可以因新证据改变，不能因重新生成改变」。
